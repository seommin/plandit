# 0006. AI 일정 비서의 도구 호출 루프는 한 단계씩 DB에 남기며 진행하고, 일정 변경은 승인 뒤에만 실행한다

- 상태: 채택 (PLANDIT-21)
- 관련 코드: `apps/api/src/assistant/assistant.service.ts`, `apps/api/src/assistant/assistant-tools.ts`, `apps/api/src/ai/anthropic.adapter.ts`

## 맥락

"내일 오후에 1시간 회의 잡아줘"를 처리하려면 모델이 도구를 여러 번 부른다(캘린더 확인 → 빈 시간 찾기 → 일정 만들기). 일정을 만드는 도구는 사용자가 확인해야 하는데, 그 확인은 몇 초에서 몇 분 뒤 **다른 HTTP 요청**으로 온다.
루프 한 번에 LLM 호출이 여러 번 일어나고, 호출마다 값이 다르다([0005](0005-ai-credit-reserve-settle.md)). 워커는 루프 중간에 죽을 수 있다.
Claude Opus 5.5는 thinking 블록을 대화에 묶어 둔다. 앞부분(시스템 프롬프트·도구 목록·이전 메시지)이 한 바이트라도 바뀐 대화에 예전 thinking 블록을 다시 보내면 400이고, 강제 `tool_choice`도 400이다.

## 결정

1. **루프는 수동으로, 상태는 DB에.** SDK의 도구 실행기는 한 프로세스 안에서 끝까지 도는 루프라 승인 대기에서 멈췄다 다른 요청으로 이어갈 수 없다. 대화(`AssistantMessage`)와 도구 호출(`AssistantToolCall`)을 저장하고, 워커는 마지막으로 저장된 상태를 보고 다음 한 걸음만 진행한다. 어디서 멈췄다 다시 돌려도 같은 곳에서 이어진다.
2. **LLM 호출 1번 = AI 사용 건 1건.** 단계마다 [0005](0005-ai-credit-reserve-settle.md)의 선차감 → 실행 → 정산을 그대로 쓴다. 다음 호출은 스레드 행을 잠그고 예약해 `pendingUsageId`에 적으므로 워커가 재시도하거나 둘이 동시에 돌아도 같은 단계를 두 번 예약·호출하지 않는다. 응답과 도구 호출 행은 정산 트랜잭션 안에서 저장된다.
3. **한도는 단계 수와 잔액.** 메시지 하나에 `ASSISTANT_MAX_STEPS`번까지 부르고, 매 단계 선차감이 실패하면(잔액 부족) 그 자리에서 멈춘다. 끝난 단계는 결과를 냈으므로 청구하고, 실패한 호출만 환불한다.
4. **변경 도구는 승인 뒤에만.** 읽기 도구는 바로 실행하고, `create_event`는 입력 검증과 권한 확인을 통과하면 승인 카드(`preview`)로 기다린다. 승인할 때 권한을 **다시** 확인하고 일정 생성과 결과 기록을 한 트랜잭션으로 한다. 거절·실패도 결과로 모델에 돌려줘 이어서 답하게 한다.
5. **대화는 append-only, 앞부분은 고정.** 모델 응답은 받은 블록(thinking 포함) 그대로 저장해 다시 보낸다. 시스템 프롬프트와 도구 목록은 대화 내내 같고, 바뀌는 "지금 시각·시간대"는 사용자 메시지 첫 줄에 넣는다. 덤으로 프롬프트 캐시가 단계마다 앞부분을 재사용한다.
6. **도구는 요청자가 API로 할 수 있는 것만.** 일정 조회는 일정 목록 API와 같은 공개 범위, 만들기는 `POST /events`와 같은 캘린더 역할. 빈 시간은 요청자가 볼 수 있는 일정으로만 계산하고, 결과에 그 사실을 적어 모델이 사용자에게 알린다.

## 버린 대안

- **SDK 도구 실행기 + 승인 대기 동안 프로세스에서 기다리기**: 사용자가 시트를 닫거나 배포로 프로세스가 바뀌면 대화가 사라진다. 기다리는 동안 워커 슬롯도 묶인다.
- **메시지 하나 = AI 사용 건 하나(전체 루프를 한 번에 선차감)**: 단계 수를 미리 모르므로 상한이 단계 수 × 최대 호출 값으로 커지고, 선차감 동안 잔액이 크게 묶인다. 정산도 루프가 끝날 때까지 미뤄진다.
- **팀원의 개인 일정까지 "바쁨"으로 보기**: "팀 전원이 되는 시간"이 정확해지지만 워크스페이스 역할로 캘린더 데이터를 보게 되어 권한 규칙(워크스페이스 역할과 캘린더 권한을 섞지 않는다)에 예외가 생긴다.
- **도구 강제 호출로 단계 고정**: Opus 5.5는 강제 `tool_choice`를 거절한다. `auto` + 프롬프트 안내 + `strict` 스키마를 쓴다.

## 결과

- 승인 대기 중 시트를 닫았다 열어도, 워커가 재시작돼도 대화가 그대로 이어진다.
- 단계별 도구 입력·결과·소요 시간과 호출별 토큰·크레딧이 남는다.
- 대가: 단계마다 폴링(1.5초)으로 화면을 갱신하므로 스트리밍처럼 글자가 흐르지 않는다. 대화가 길어질수록 매 단계 선차감도 커진다(정산 때 돌려줌).

## 이 결정을 지키는 테스트

- `apps/api/test/assistant.e2e-spec.ts`: 승인 전 일정 0건, 동시 승인 3번 → 1건, 기다리는 사이 권한이 빠지면 실행 안 함, 워커 두 개 동시 → 호출 수 그대로, 단계 한도, 단계 중 잔액 부족, LLM 오류 시 그 호출만 환불, 모델이 받은 대화의 앞부분이 그대로, 남의 개인 일정은 도구 결과에 없음, 실제 BullMQ 워커로 끝까지
- `apps/api/src/assistant/assistant.spec.ts`: 도구 목록·스키마 고정, 시스템 프롬프트에 날짜 없음
- `apps/api/src/ai/anthropic.adapter.spec.ts`: strict 도구, `tool_choice` 없음, 응답 블록을 그대로 다시 보냄
